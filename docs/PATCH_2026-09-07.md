# 사건 순서 및 위험 재발 패치 — 2026-09-07

## 수정

- 최초 훼손 블록은 이력용으로 보존하고 현재 상태와 분리했다.
- 현재 상태는 증명된 소스 위치(블록, 트랜잭션 인덱스, 영수증 로그 인덱스)가 가장 나중인 사건으로 결정한다.
- 훼손 → 복구 → 재훼손에서 신규 여신이 다시 차단된다.
- 먼저 수신한 복구 증명도 보존한다. 복구만 있으면 NO_PROOF이며, 훼손도 증명되면 사건 순서에 따라 상태를 결정한다.
- 기존 자산의 소스 체인 변경을 거절해 다른 체인의 사건 이력이 섞이지 않도록 했다.
- latestEvents 조회를 추가했다. 기존 Asset 조회 및 submitEvent 입력 형식은 유지했다.
- restoredAt은 최신 증명 복구 블록이며 현재 상태 판정에는 statusOf를 사용해야 한다.
- Restored 이벤트는 복구 사건이 최신으로 수신되었다는 뜻이다. 복구만 증명된 경우 statusOf는 NO_PROOF이므로 소비자는 이벤트만으로 여신을 허용하면 안 된다.

- 실제 메인넷 증명 데이터 및 실제 디코더를 사용하는 테스트도 로컬 EVM에서 통과했다. BlockProver는 로컬 모형이므로 수정본의 CC3 실배포 검증을 대신하지 않는다.

## 적용 상태와 남은 일

이 패치는 로컬 복사본에만 적용됐다. 커밋·푸시·DoraHacks 수정·테스트넷 재배포는 수행하지 않았다.
기존 공개 주소는 수정 전 계약이다. 새 EligibilityLedger와 이를 참조하는 GatedCreditLine을 배포하고 설정 및 필요한 사건 증명을 재입력한 뒤 새 주소로 제출 문서를 갱신해야 한다.
기존 이력이 자동으로 이동하지 않으며, 이 계약은 업그레이드 프록시가 아니다.

NO_PROOF의 여신 허용 정책, 누락 증명/중계 지연, ERC20 반환값 처리, 가격 및 소수점 기반 LTV는 이번 사건 순서 패치 범위 밖이다. 전체 제품의 안전성을 인증하는 결과가 아니다.

## 재현

contracts 디렉터리에서 의존성을 설치한 후:

```text
node scripts/compile.js
node test/eligibility.test.js
node test/ledger.test.js
node test/realdata-eligibility.test.js
node test/realdata.test.js
```

이 PC에서는 Node에 NODE_USE_SYSTEM_CA=1을 설정해 운영체제의 신뢰 인증서를 사용했다. TLS 검증을 비활성화하지 않았다.
